L94@P1: In this section, some fundamentals on Boolean networks,

L99@P1: A. General Terms and Definitions
L100@P1: A Boolean network is a directed acyclic graph (DAG) where
L101@P1: nodes correspond to logic gates and directed edges represent
L102@P1: wires connecting the gates. It is assumed that each node has a
L103@P1: unique ID (integer number). A fanin (fanout) cone of node n
L104@P1: is a subset of all nodes of the network reachable through the
L105@P1: fanin (fanout) edges from the given node. A node n has zero or
L106@P1: larger fanin (nodes driving n) and zero or larger fanout (nodes
L107@P1: driven by n). The primary inputs (PIs) are nodes without fanin,
L108@P1: whereas the primary outputs (POs) are a subset of nodes from
L109@P1: the network connecting it to the environment.
L110@P1: AND-inverter graph (AIG) is a particular DAG where each
L111@P1: node has either zero incoming edges (in the case of PI) or two
L112@P1: incoming edges (in the case of AND node). Each edge can be
L113@P1: complemented or not. Some nodes are marked as PO.
L114@P1: Moreover, in terms of structural cuts,a cut c of a node
L115@P1: n is a set of nodes in the network, called leaves of the cut,
L116@P1: such that every path between a PI and n contains a node in
L117@P1: c. A cut of n is irredundant if no subset on it is a cut. A
L118@P1: K-feasible cut contains K or fewer nodes. Node n is called
L119@P1: the root of cut c. The cut size is the number of its leaves.
L120@P1: A trivial cut is the node itself. A local function of an AIG
L121@P1: node n, denoted by fn(x), is a Boolean function of the logic
L122@P1: cone rooted in n and expressed in terms of the leaves x of a
L123@P1: cut of n. Cut enumeration is a technique used by a cut-based
L124@P1: technology mapper to perform cut computation using dynamic
L125@P1: programming, starting from PI and ending at PO [15], [16].
L126@P1: Furthermore, in terms of classes of functions, a set of all
L127@P1: functions with up to n variables can be grouped taking into
L128@P1: account the negation (N), and/or the permutation (P) of variables, and/or the negation of the function value, so creating
L129@P1: NPN representatives [17]. For instance, NP-class corresponds
L130@P1: to the set of distinct functions obtained by negating and/or permuting the input variables. Similarly, NPN-class corresponds
L131@P1: to the set of distinct functions obtained by negating and/or
L132@P1: permuting the input variables and/or negating the function
L133@P1: value.

L154@P1: A TLF has also been called “linearly separable” function.
L155@P1: Although some complex functions are TLFs, there exist
L156@P1: some simple functions that are not TLF. For instance, the
L157@P1: function h = x1x2 + x3x4 cannot be represented in terms
L158@P1: of input weights and threshold value. The threshold logic
L159@P1: identification process verifies if a given Boolean function is
L160@P1: TLF (or not) and compute the input weights and the corresponding threshold value. In this paper, we have adopted
L161@P1: the identification process presented in [19], instead of the
L162@P1: integer-linear-programming (ILP)-based algorithms applied in
L163@P1: previous works [7]–[10], [20]. This is mainly due to the fast
L164@P1: runtime and good QoRs obtained. In such an approach, a complete system of inequalities is also built using a similar strategy
L165@P1: to ILP inequalities generation algorithms. However, unlike
L166@P1: ILP-based approaches, the inequalities system is not solved.
L167@P1: Instead, the algorithm speeds up the process by selecting some
L168@P1: of the inequalities as constraints to the associated variables and
L169@P1: computing the variable (input) weights in a bottom-up strategy. After this assignment, the consistency of the entire system
L170@P1: is verified in order to check whether the weights have been
L171@P1: correctly computed.
L172@P1: In the context of structural cuts, we call a threshold cut that
L173@P1: the corresponding Boolean function is TLF.

L175@P1: that physically embodies the behavior expressed in (1). TLGs
L176@P1: can represent the implementation of complex functions. For
L177@P1: instance, the TLG defined by [4, 3, 3, 1, 1; 7] corresponds to
L178@P1: f = x1x2+x1x3+x2x3x4+x2x3x5. Using larger threshold functions has the potential benefit of reducing the total number of
L179@P1: gates needed to implement digital circuits. Several topologies
L180@P1: of TLGs have been proposed for CMOS and emerging nanotechnologies. A survey with more than 50 TLG circuitries are
L181@P1: presented by Beiu et al. [21]. Moreover, TLG designs based
L182@P1: on memristors [1], spintronics devices [4], and RTDs [7] have
L183@P1: also been proposed.

L186@P1: to the sum of the TLG areas. Notice that the TLG area
L187@P1: depends directly on the technology adopted to build such a
L188@P1: gate. However, since no threshold-oriented technology currently available is mature enough to fabricate reliable TLGs in
L189@P1: large scale, synthesis tools usually consider that each threshold gate presents the same area. Therefore, the total circuit
L190@P1: area is usually estimated through the overall number of TLGs
L191@P1: instantiated in the mapped circuit.

L216@P2: C. LUT-Based Technology Mapping
L217@P2: Common area and delay design cost criteria for TLS are,
L218@P2: respectively, the TLG count and the circuit logic depth.
L219@P2: Therefore, it is straightforward to relate TLS with LUT-based
L220@P2: technology mapping.
L221@P2: The technology mapping process transforms a technologyindependent logic network, named subject graph, into a
L222@P2: network of logic nodes. In SRAM-based FPGA, each logic
L223@P2: node is represented by a K-input LUT implementing any
L224@P2: Boolean function up to K variables [15]. The subject graph
L225@P2: is often represented as an AIG.
L226@P2: The performance of FPGA-based circuit is determined by
L227@P2: two factors, the delay in K-LUTs and the delay due to the
L228@P2: interconnection wires. Each K-LUT has a constant delay independent of the function configured, which represents the access
L229@P2: time of a K-LUT. The interconnection delay is dominated by
L230@P2: the physical configuration of the FPGA architecture, which
L231@P2: is not available during the logic synthesis. Thus, LUT-based
L232@P2: technology mappers assume that each edge in the mapping
L233@P2: solution has a constant delay. Due to these reasons, the circuit
L234@P2: delay is commonly represented by the circuit logic depth and
L235@P2: the circuit area is represented by the number of K-LUTs from
L236@P2: the mapped solution.
L237@P2: Technology mappers for FPGA produce near-optimum logic
L238@P2: depth while minimizing the number of LUTs in the resulting
L239@P2: network [15], [22], [23]. A typical procedure comprises the
L240@P2: following steps.
L241@P2: 1) Near-optimum delay mapping: computes arrival time at
L242@P2: each node by computing the depth of priority cuts and
L243@P2: choosing the best one.
L244@P2: 2) Area recovery: reduces area using several heuristics, for
L245@P2: instance, area flow and exact local area [14].
L246@P2: 3) Choose the resulting cover.
L247@P2: Notice that the logic depth optimality is only achievable by
L248@P2: this procedure because the delay-oriented mapping problem
L249@P2: has two important properties: 1) its optimal solution can be
L250@P2: obtained by using the optimal solution from its subproblems
L251@P2: and 2) its subproblems overlap, i.e., solutions of same subproblems are repeatedly needed. With this, through dynamic
L252@P2: programming, choosing the best cut of a node is incrementally
L253@P2: solving the mapping problem from inputs to outputs.
L254@P2: Moreover, circuit logic depth optimality requires the computation of all cuts in delay mapping, which is not scalable,
L255@P2: i.e., the number of K-cuts in a given network with n nodes is
L256@P2: O(nK). In order to avoid exhaustive computation, the concept
L257@P2: of priority cuts allows for the computation of a small number C of K-cuts at each node (typically 4 ≤ C ≤ 8). The
L258@P2: priority cut computation does not guarantee depth optimality. However, the circuit logic depth is optimal in 95% of the
L259@P2: cases [24]. This one-pass, depth-oriented mapping increases
L260@P2: substantially the number of LUTs, which is brought down on
L261@P2: the area recovery step [15], [22].
L262@P2: III. RELATED WORKS
L263@P2: The goal of TLS is to generate a TLN where each TLF can
L264@P2: be directly implemented through a single TLG. The design
L265@P2: flow adopted by previous works starts by performing an LUTbased technology mapping [7]–[11]. This first mapping task
L266@P2: results in a netlist of Boolean functions with restricted fanin.
L267@P2: Afterwards, these methods identify which Boolean functions
L268@P2: are TLF and then include them into the final solution. For each
L269@P2: non-TLF, they generate a subnetwork. The main differences
L270@P2: among these approaches are: 1) the procedure of the threshold
L271@P2: logic identification and 2) the generation of the sub-TLN from
L272@P2: a nonthreshold function.
L273@P2: Zhang et al. [7] and Subirats et al. [8] used ILP to perform
L274@P2: the TLF identification. For non-TLFs, the Zhang’s method
L275@P2: decomposes the function into AND/OR subfunctions, which
L276@P2: are always TLFs, and select nodes through a heuristic way in
L277@P2: order to combine them, checking whether the resulting function is TLF. The Subirats’ approach, on the other hand, is
L278@P2: based on the function truth table description. It selects recursively a variable and performs the Shannon decomposition up
L279@P2: to find TLF subfunctions. The Subirats’ method improves the
L280@P2: Zhang’s results in terms of the number of gates and circuit
L281@P2: logic depth. However, the Subirats’ approach produces only
L282@P2: two-level TLNs without fanin restrictions, being more suitable
L283@P2: to neural network design.
L284@P2: Gowda et al. [9] proposed a heuristic approach to identify
L285@P2: TLF. They adopt both binary decision diagrams (BDDs) and a
L286@P2: factorized tree structure [called max literal factor tree (MLFT)]
L287@P2: in order to generate a TLN. The method breaks recursively the
L288@P2: initial expression tree into subexpressions, identifying subtrees
L289@P2: that represent TLF and assigning input weights. The method
L290@P2: proposed by Palaniswamy and Tragoudas [10], improves the
L291@P2: Gowda’s approach [9]. It looks for circuit outputs that can
L292@P2: be implemented as a single TLF. Both the Gowda’s and the
L293@P2: Palaniswamy’s methods suffer from execution time as the main
L294@P2: bottleneck, and the solutions depend strongly on the initial
L295@P2: structure (BDD or MLFT), in particular, on the ordering of
L296@P2: tree nodes.
L297@P2: The method proposed by Neutzling et al. [11], is based
L298@P2: on a TLG association process through the principle called
L299@P2: functional composition, which is based on dynamic programming [26]. The algorithm associates simpler subsolutions, with

L340@P3: IV. PROPOSED THRESHOLD LOGIC SYNTHESIS
L341@P3: Given a digital circuit functionality, usually described in
L342@P3: RTL format, the TLS relies on finding an optimized TLN.
L343@P3: The most TLS tools initially cover the circuit by singleoutput nodes, disregarding their thresholdness, as illustrated in
L344@P3: Fig. 1(a) [7]–[11]. Then, these approaches perform the resynthesis of any non-TLF found to individual, unshared sub-TLN
L345@P3: in order to provide the covering of the final TLN.
L346@P3: In [25], we propose a logic synthesis flow that identifies
L347@P3: TLFs before the circuit covering task. It is based on a threestage procedure, as depicted in Fig. 1(b): 1) a complete cut
L348@P3: enumeration, storing Boolean functions of cuts in the design;
L349@P3: 2) the identification of TLFs related to this set of computed
L350@P3: cuts; and 3) the technology mapping considering thresholdness of precomputed functions. By doing so, this approach
L351@P3: is able to discard non-TLF cuts and provides the corresponding threshold network from the first covering action. Such a
L352@P3: strategy allows the exploitation of multiobjective technology
L353@P3: mapping algorithms, as described in Section II-C. On the other
L354@P3: hand, notice that this approach relies on computing cuts twice
L355@P3: in the flow, in the stages 1) and 3), mentioned above.
