L406: # torch.compilercite232†#
L407: 
L408: Created On: Jul 28, 2023 | Last Updated On: Jul 20, 2026
L409: 
L410: `torch.compiler` is a namespace through which some of the internal compiler methods are surfaced for user consumption. The main function and the feature in this namespace is `torch.compile`.
L411: `torch.compile` is a PyTorch function introduced in PyTorch 2.x that aims to solve the problem of accurate graph capturing in PyTorch and ultimately enable software engineers to run their PyTorch programs faster. `torch.compile` is written in Python and it marks the transition of PyTorch from C++ to Python.
L412: 
L413: `torch.compile` leverages the following underlying technologies:
L414:   * TorchDynamo (torch._dynamo) is an internal API that uses a CPython feature called the Frame Evaluation API to safely capture PyTorch graphs. Methods that are available externally for PyTorch users are surfaced through the `torch.compiler` namespace.
L415:   * TorchInductor is the default `torch.compile` deep learning compiler that generates fast code for multiple accelerators and backends. You need to use a backend compiler to make speedups through `torch.compile` possible. For NVIDIA, AMD and Intel GPUs, it leverages OpenAI Triton as the key building block.
L416:   * AOT Autograd captures not only the user-level code, but also backpropagation, which results in capturing the backwards pass “ahead-of-time”. This enables acceleration of both forwards and backwards pass using TorchInductor.
L417: 
L418: To better understand how `torch.compile` tracing behavior on your code, or to learn more about the internals of `torch.compile`, please refer to the cite122†`torch.compile` programming model .
L419: 
L420: Note
L421: In some cases, the terms `torch.compile`, TorchDynamo, `torch.compiler` might be used interchangeably in this documentation.
L422: `torch.compiler` also includes an ahead-of-time API, `torch.compiler.precompile`. It captures a whole computation `fn(*example_inputs)` – with the model(s) passed among `example_inputs`, e.g. `precompile(lambda model, x: model(x), model, x)` – and lowers it to a self-contained, runnable Python source string plus an acceleration cache. Reload the artifact with `torch.compiler.precompile.load`; since no weights are baked in, you pass the model again at runtime. See the cite233†API reference for details.
L423: Warning
L424: 
L425: `torch.compile` may not support recently released major versions of Python.
L426: 
L427: If you attempt to use `@torch.compile` in an unsupported Python environment, you may encounter an error similar to:
L428: 
L429:     RuntimeError: torch.compile is not supported on Python 3.xx.0+
L430: 
L431: 
L432: 
L433: Please ensure that your current Python version is within the range supported by PyTorch for `torch.compile`.
L434: If you have installed PyTorch on a Python version that is too new, you will need to switch to an earlier Python version in order to use `torch.compile`.
L435: As mentioned above, to run your workflows faster, `torch.compile` through TorchDynamo requires a backend that converts the captured graphs into a fast machine code. Different backends can result in various optimization gains. The default backend is called TorchInductor, also known as inductor, TorchDynamo has a list of supported backends developed by our partners, which can be seen by running `torch.compiler.list_backends()` each of which with its optional dependencies.
L436: Some of the most commonly used backends include:
L437: 
L438: Training & inference backends
L439: 
L440: Backend  | Description
L441: --- | ---
L442: `torch.compile(m, backend="inductor")`  | Uses the TorchInductor backend. cite234†Read more†dev-discuss.pytorch.org
L443: `torch.compile(m, backend="cudagraphs")`  | CUDA graphs with AOT Autograd. cite235†Read more†pytorch.org
L444: `torch.compile(m, backend="ipex")`  | Uses IPEX on CPU. cite236†Read more†github.com
L445: 
L446: Inference-only backends
L447: Backend  | Description
L448: --- | ---
L449: `torch.compile(m, backend="tensorrt")`  | Uses Torch-TensorRT for inference optimizations. Requires `import torch_tensorrt` in the calling script to register backend. cite237†Read more†github.com
L450: `torch.compile(m, backend="ipex")`  | Uses IPEX for inference on CPU. cite236†Read more†github.com
L451: `torch.compile(m, backend="tvm")`  | Uses Apache TVM for inference optimizations. cite238†Read more†tvm.apache.org
