L166: # verilog2nn
L167: 
L168: Compile Verilog combinational logic into equivalent PyTorch neural networks. No training, no approximation — the network computes the exact same function as the original circuit, for all inputs.
L169: ## Why?
L170: 
L171: Jane Street published a cite80†puzzle†blog.janestreet.com where they hand-built a neural network that computed MD5, then challenged people to reverse-engineer it. The solver found that the network implemented logic gates via ReLU layers — AND, OR, XOR all have clean representations as small linear+ReLU combos.
L172: That got me thinking: if you can hand-build a circuit-as-NN, why not automate it? Take any Verilog module, synthesize it down to gates, and mechanically map each gate to its ReLU equivalent. The result is a neural network that is provably equivalent to the original circuit — not trained to approximate it, but constructed to replicate it exactly.
L173: ## How it works
L174: 
L175:     `Verilog → Yosys (synthesize to AND+NOT) → JSON netlist → topological sort → SparseLinear+ReLU MLP → PyTorch model
L176:     `
L177:   1. Yosys frontend: reads your `.v` file, flattens hierarchy, maps everything to AND+NOT gates via ABC (`abc -g AND`). AND+NOT is functionally complete — any Boolean function can be expressed with just these two gates.
L178:   2. Netlist parser: builds a gate-level DAG from Yosys's JSON output
L179:   3. Topological sort: assigns gates to layers — gates in the same layer have no dependencies on each other
L180:   4. Gate mapping: AND gates become ReLU neurons, NOT gates are folded into weights:
L181: Gate  | Formula  | Neural network equivalent
L182: --- | --- | ---
L183: AND(a,b)  | ReLU(a + b − 1)  | SparseLinear (weights: +1, +1, bias: −1) → ReLU
L184: AND(a, NOT(b))  | ReLU(a − b)  | SparseLinear (weights: +1, −1, bias: 0) → ReLU
L185: AND(NOT(a), NOT(b))  | ReLU(−a − b + 1)  | SparseLinear (weights: −1, −1, bias: +1) → ReLU
L186: NOT gates don't produce separate neurons — they're absorbed into the SparseLinear weights of downstream AND gates. This means every layer is just SparseLinear → ReLU, a clean MLP architecture.
L187: 
L188: The generated model consists of:
L189: 
L190:   * `sparse_linear.py` — `SparseLinear(nn.Module)` using COO format weights
L191:   * `model.py` — `VerilogNN(nn.Module)` stacking SparseLinear + ReLU layers
L192:   * `weights.safetensors` — sparse weights in COO format (indices + values + bias per layer)
L193: ## Quick start
L194: 
L195:     pip install -e .
L196:     # you also need: yosys, iverilog (for verification)
L197: 
L198:     # compile a Verilog module to a PyTorch model
L199:     verilog2nn tests/verilog/adder4.v -o output/
L200: 
L201:     # this produces:
L202:     #   output/sparse_linear.py    — SparseLinear module
L203:     #   output/model.py            — nn.Module definition
L204:     #   output/weights.safetensors — model weights (COO sparse)
L205:     #   output/inference.py        — standalone inference script
L206: ## Demo: 4-bit adder
L207: 
L208: Given a simple ripple-carry adder:
L209: 
L210:     module adder4(input [3:0] a, input [3:0] b, output [4:0] sum);
L211:       assign sum = a + b;
L212:     endmodule
L213: verilog2nn synthesizes it down to AND+NOT gates, folds NOTs into weights, and produces a pure SparseLinear → ReLU MLP that maps 8 input bits → 5 output bits. Exhaustive verification over all 256 input combinations confirms exact equivalence:
L214: 
L215:     `$ python tests/run_tests.py
L216:     ...
L217:     === T4: 4-bit Adder ===
L218:       Verified 256/256 inputs: ALL MATCH
L219:       PASSED
L220:     `
L221: The test suite also covers crypto-scale circuits: full MD5 (~52K gates), SHA-256 (~136K gates), and AES-128 (~171K gates), all verified bit-exact against iverilog simulation.
