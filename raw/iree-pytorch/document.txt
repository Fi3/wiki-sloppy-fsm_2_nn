L236: ## Overviewcite16†link
L237: 
L238: cite139†iree-turbine†github.com offers a tight integration between compatible versions of IREE, cite140†torch-mlir†github.com , and cite141†PyTorch†pytorch.org .
L239: 
L240:   * [Input] Seamless integration with standard PyTorch workflows
L241:   * [Input] Deployment support for running PyTorch models on cloud and edge devices
L242:   * [Input] General purpose model compilation and execution tools
L243: Both just-in-time (JIT) and ahead-of-time (AOT) workflows are supported:
L244: 
L245:     `graph LR
L246:       accTitle: PyTorch integration overview
L247:       accDescr {
L248:         PyTorch programs can be optimized within a Python session with
L249:         iree-turbine's just-in-time tools.
L250:         PyTorch programs can be exported out of Python to native binaries using
L251:         iree-turbine's ahead-of-time export toolkit.
L252:       }
L253: 
L254:       subgraph Python
L255:         pytorch(PyTorch)
L256:         subgraph turbine [iree-turbine]
L257:           jit("Eager execution (JIT)")
L258:           aot("Export toolkit (AOT)")
L259:         end
L260: 
L261:         pytorch --> jit
L262:         jit --> pytorch
L263:         pytorch --> aot
L264:       end

L312: ## Just-in-time (JIT) executioncite18†link
L313: Just-in-time integration allows for Python code using TorchDynamo to optimize PyTorch models/functions using IREE, all within an interactive Python session.
L314: 
L315:     `graph TD
L316:       accTitle: PyTorch JIT workflow overview
L317:       accDescr {
L318:         Programs start as either PyTorch nn.Module objects or callable functions.
L319:         Programs are compiled into optimized modules using torch.compile.
L320:         Within torch.compile, Dynamo runs the program through Turbine and IREE.
L321:       }
L322: 
L323:       subgraph Python
L324:         input([nn.Module / function])
L325: 
L326:         subgraph compile ["torch.compile()"]
L327:           direction LR
L328:           dynamo{{TorchDynamo}}
L329:           turbine{{iree-turbine}}
L330:           iree{{IREE}}
L331:           dynamo --> turbine --> iree
L332:         end
L333: 
L334:         output([Optimized module])
L335:         input --> compile --> output
L336:       end`
L337: For deployment outside of Python, see the cite21†ahead-of-time sections below .
L338: ### Quickstartcite19†link
L339: 
L340: Turbine integrates into PyTorch as a cite146†custom backend†pytorch.org for cite147†`torch.compile`†pytorch.org .
L341: Behind the scenes, PyTorch captures the structure of the input model into a computation graph and feeds that graph through to the selected backend compiler.
L342: 
L343:     `import torch
L344: 
L345:     # Define the `nn.Module` or Python function to run.
L346:     class LinearModule(torch.nn.Module):
L347:       def __init__(self, in_features, out_features):
L348:         super().__init__()
L349:         self.weight = torch.nn.Parameter(torch.randn(in_features, out_features))
L350:         self.bias = torch.nn.Parameter(torch.randn(out_features))
L351: 
L352:       def forward(self, input):
L353:         return (input @ self.weight) + self.bias
L354: 
L355:     linear_module = LinearModule(4, 3)
L356: 
L357:     # Compile the program using the turbine backend.(1)
L358:     opt_linear_module = torch.compile(linear_module, backend="turbine_cpu")
L359: 
L360:     # Use the compiled program as you would the original program.
L361:     args = torch.randn(4)
L362:     turbine_output = opt_linear_module(args)
L363:     `
L364:   1. Initial integration only supports CPU, but support for many of IREE's other targets is coming soon.

L372: ## Ahead-of-time (AOT) exportcite21†link
L373: 
L374: The ahead-of-time toolkit allows developers to define a program's structure in Python and then export deployment-ready artifacts that can be used in IREE's cite31†deployment configurations via the cite43†API bindings .
L375: ### Simple APIcite22†link
L376: For simple models, a one-shot export API is available.
L377: 
L378:     `graph LR
L379:       accTitle: PyTorch simple AOT workflow overview
L380:       accDescr {
L381:         Programs start as PyTorch nn.Module objects.
L382:         Modules are exported using the "aot" API.
L383:         Exported outputs are then compiled to .vmfb files with executable binaries.
L384:       }
L385: 
L386:       subgraph Python
L387:         input([nn.Module])
L388:         export(["ExportOutput (MLIR)"])
L389:         input -- "aot.export()" --> export
L390:       end
L391:       subgraph Native
L392:         binary(["binary (.vmfb)"])
L393:       end
L394: 
L395:       export -. "compile()" .-> binary`
L396: 
L397:     `import iree.runtime as ireert
L398:     import numpy as np
L399:     import iree.turbine.aot as aot
L400:     import torch
L401: 
L402:     # Define the `nn.Module` to export.
L403:     class LinearModule(torch.nn.Module):
L404:       def __init__(self, in_features, out_features):
L405:         super().__init__()
L406:         self.weight = torch.nn.Parameter(torch.randn(in_features, out_features))
L407:         self.bias = torch.nn.Parameter(torch.randn(out_features))
L408: 
L409:       def forward(self, input):
L410:         return (input @ self.weight) + self.bias
L411: 
L412:     linear_module = LinearModule(4, 3)
L413: 
L414:     # Export the program using the simple API.
L415:     example_arg = torch.randn(4)
L416:     export_output = aot.export(linear_module, example_arg)
L417: 
L418:     # Compile to a deployable artifact.
L419:     binary = export_output.compile(save_to=None)
L420: 
L421:     # Use the IREE runtime API to test the compiled program.
L422:     config = ireert.Config("local-task")
L423:     vm_module = ireert.load_vm_module(
L424:         ireert.VmModule.copy_buffer(config.vm_instance, binary.map_memory()),
L425:         config,
L426:     )
L427:     input = np.array([1.0, 2.0, 3.0, 4.0], dtype=np.float32)
L428:     result = vm_module.main(input)
L429:     print(result.to_host())
L430:     `

L438: ### Advanced APIcite24†link
L439: For more complex models, an underlying advanced API is available that gives access to more features.
L440: 
L441:     `graph LR
L442:       accTitle: PyTorch advanced AOT workflow overview
L443:       accDescr {
L444:         Programs are represented using the aot.CompiledModule class.
L445:         CompiledModules can extend nn.Module objects, export globals, and set
L446:         shapes and dtypes for each function.
L447:         Modules are exported using the "aot" API.
L448:         Exported outputs are then compiled to .vmfb files with executable binaries.
L449:       }
L450: 
L451:       subgraph Python
L452:         compiledmodule("aot.CompiledModule<br><br>- extend nn.Module<br>- export globals<br>- set shapes/dtypes")
L453:         export(["ExportOutput (MLIR)"])
L454:         compiledmodule -- "aot.export()" --> export
L455:       end
L456: 
L457:       subgraph Native
L458:         binary(["binary (.vmfb)"])
L459:       end
L460: 
L461:       export -. "compile()" .-> binary`
L462: Advanced export workflows can use the cite152†`aot.CompiledModule`†github.com class to define and constrain the structure of a program prior to compiling it.
L463: 
L464:     `import iree.turbine.aot as aot
L465: 
L466:     # A minimal program, with no functions or variables.
L467:     class BasicModule(aot.CompiledModule):
L468:       ...
L469: 
L470:     # Create an instance of the program and convert it to MLIR.
L471:     from iree.compiler.ir import Context
L472:     instance = BasicModule(context=Context())
L473:     module_str = str(aot.CompiledModule.get_mlir_module(instance))
L474: 
L475:     print(module_str)
L476:     # module @basic {
L477:     # }
L478:     `
L479: #### Exporting functionscite25†link
L480: 
L481: Exported functions are the API entry points into a compiled program.
L482: 
L483: Simple feed-forward neural networks used for inference may have a single exported function (typically called "forward"), while more complex programs can have multiple computation functions, initialization functions, "backward" methods for training, state management functions, debugging functions, etc.
L484: #### Global variablescite26†link
L485: 
L486: Global variables are used to represent persistent state within a program instance.
L487: 
L488: For example, they can be used to represent the weights and biases in a neural network, and exporting these as mutable variables can allow for setting their values independently at runtime.
L489:   * Individual globals can be exported using `aot.export_global()`:
L490: 
L491:     `state_example = torch.zeros([1], dtype=torch.int32)
L492: 
L493:     class SampleModule(aot.CompiledModule):
L494:       value = aot.export_global(state_example, mutable=True)
L495: 
L496:       def get_value(self):
L497:         return self.value
L498: 
L499:       def update_value(self, new_value=aot.abstractify(value)):
L500:         self.value = new_value
L501:     `
L502: #### Using external parameterscite27†link
L503: 
L504: Model parameters can be stored in standalone files that can be efficiently stored and loaded separately from model compute graphs. See the cite38†Parameters guide for more general information about parameters in IREE.
L505: 
L506: When using iree-turbine, the `aot.externalize_module_parameters()` function separates parameters from program modules and encodes a symbolic relationship between them so they can be loaded at runtime.
L507: We use cite153†Safetensors†huggingface.co here to store the models parameters on disk, so that they can be loaded later during runtime.
L508: 
L509:     `import torch
L510:     from safetensors.torch import save_file
L511:     import numpy as np
L512:     import iree.turbine.aot as aot
L513: 
L514:     class LinearModule(torch.nn.Module):
L515:         def __init__(self, in_features, out_features):
L516:             super().__init__()
L517:             self.weight = torch.nn.Parameter(torch.randn(in_features, out_features))
L518:             self.bias = torch.nn.Parameter(torch.randn(out_features))
L519: 
L520:         def forward(self, input):
L521:             return (input @ self.weight) + self.bias
L522: 
L523:     linear_module = LinearModule(4,3)
L524: 
L525:     # Create a params dictionary. Note that the keys here match LinearModule's
L526:     # attributes. We will use the saved safetensor file for use from the command
L527:     # line.
L528:     wt = linear_module.weight.data.contiguous()
L529:     bias = linear_module.bias.data.contiguous()
L530:     params = { "weight": wt, "bias": bias }
L531:     save_file(params, "params.safetensors")
L532: 
L533:     # Externalize the model parameters. This removes weight tensors from the IR
L534:     # module, allowing them to be loaded at runtime. Symbolic references to these
L535:     # parameters are still retained in the IR.
L536:     aot.externalize_module_parameters(linear_module)
L537: 
L538:     input = torch.randn(4)
L539:     exported_module = aot.export(linear_module, input)
L540:     # Compile the exported module, to generate the binary. When `save_to` is
L541:     # not None, the binary will be stored at the path passed in to `save_to`.
L542:     # Here, we pass in None, so that the binary can stored in a variable.
L543:     binary = exported_module.compile(save_to=None)
L544: 
L545:     # Save the input as an npy tensor, so that it can be passed in through the
L546:     # command line to `iree-run-module`.
L547:     input_np = input.numpy()
L548:     np.save("input.npy", input_np)
L549:     `

L552: Python runtime Command line tools
L553: Runtime invocation now requires loading the parameters as a separate module. To get the parameters as a module, iree.runtime provides a convenient method, called `create_io_parameters_module()`.
L554: 
L555:     `import iree.runtime as ireert
L556: 
L557:     # To load the parameters, we need to define ParameterIndex for each
L558:     # parameter class.
L559:     idx = ireert.ParameterIndex()
L560:     idx.add_buffer("weight", wt.detach().numpy().tobytes())
L561:     idx.add_buffer("bias", bias.detach().numpy().tobytes())
L562:     # Create the runtime instance, and load the runtime.
L563:     config = ireert.Config(driver_name="local-task")
L564:     instance = config.vm_instance
L565: 
L566:     param_module = ireert.create_io_parameters_module(
L567:         instance, idx.create_provider(scope="model"),
L568:     )
L569: 
L570:     # Load the runtime. There are essentially two modules to load, one for the
L571:     # weights, and one for the main module. Ensure that the VMFB file is not
L572:     # already open or deleted before use.
L573:     vm_modules = ireert.load_vm_modules(
L574:         param_module,
L575:         ireert.create_hal_module(instance, config.device),
L576:         ireert.VmModule.copy_buffer(instance, binary.map_memory()),
L577:         config=config,
L578:     )
L579: 
L580:     # vm_modules is a list of modules. The last module in the list is the one
L581:     # generated from the binary, so we use that to generate an output.
L582:     result = vm_modules[-1].main(input)
L583:     print(result.to_host())
L584:     `
L585: It is also possible to save the VMFB binary to disk, then call `iree-run-module` through the command line to generate outputs.
L586: 
L587:     `# When save_to is not None, the binary is saved to the given path,
L588:     # and a None value is returned.
L589:     binary = exported_module.compile(save_to="compiled_module.vmfb")
L590:     `
L591: The stored safetensors file, the input tensor, and the VMFB can now be passed in to IREE through the command line.
L592: 
L593:     `iree-run-module --module=compiled_module.vmfb --parameters=model=params.safetensors \
L594:                     --input=@input.npy
L595:     `
L596: 
L597: Note here that the `--parameters` flag has `model=` following it immediately. This simply specifies the scope of the parameters, and is reflected in the compiled module.
